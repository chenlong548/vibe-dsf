# PROMPT · 论文拆解任务书（论文全文 → PAPER-BRIEF）

> **给谁用**：任何 LLM。把本文件全文 + 论文全文（或 PDF 提取文本）塞给模型即可。
> **解决什么**：论文是"论证结构"，视频需要"叙事结构"——中间隔着一层翻译。
> 本任务书把翻译结果压成一个可审计的中间产物 **PAPER-BRIEF.json**：人看一眼 brief 就知道
> 片子要讲什么、数字从哪来、哪里容易讲错。
> **下一步**：PAPER-BRIEF.json + `PROMPT-SCRIPT.md` → SCENE-PLAN.json（进现有流水线）。

---

## 输入格式

```
论文：<全文文本 / PDF 提取文本，可截断至你能读的长度>
时长：<目标秒数，可省略 → 默认 24s 五段完整片（50 拍 @126BPM）>
观众：<可省略 → 默认"对计算机技术感兴趣的普通观众"，零领域前置知识>
```

## 你（模型）的任务

读论文 → 做四件事：

1. **找反常识点**：论文里什么说法会颠覆普通观众的直觉？（这是钩子的原料，按冲击力排序）
2. **画因果链**：论文的核心机制拆成 3-5 步"人话因果"，每步配一个画面直觉
3. **摘可复述数字**：能在视频里立住的数字（带单位 + 一个日常对比基准 + 论文出处定位）
4. **标防误读边界**：这条论文最容易被科普讲错的地方（统计口径、适用条件、常见过度声称）

输出**一个完整的 PAPER-BRIEF.json**（契约见 `PAPER-BRIEF.schema.md`）。

## 翻译纪律（逐条自查）

1. **只翻译，不发挥**：每个 claim 必须能在论文里指出来源；论文没说的结论一个字不加。
   数字必须写 `source`（章节/图表定位），说不出来源的数字不准进 brief。
2. **钩子必须反常识，不是猎奇**：检验标准——"普通人原以为是 A，论文说是 B"。
   "某某研究很有趣"这种假钩子不要。
3. **机制链用"人话因果"**：每步一句 ≤20 字的白话，禁止论文腔（"证明了""提出了"不算人话因果）。
4. **数字必须配对比基准**：4.7 bit 没有感觉，"抛一次硬币的答案 = 1 bit" 才有感觉。
   没有对比基准的数字观众记不住，也不许进。
5. **类比要标防误读**：每个 metaphor 都要写清"类比在哪里失效"（如"熵≠语义，不衡量有没有用"），
   进 caveats 字段。
6. **学术争议诚实处理**：论文的估计是当时条件下的（如香农对英文的统计熵 ≈4.7 bit/字母 是
   一阶近似），caveats 必须写清现代口径，避免科普视频被较真党打脸。
7. **量力选时长**：5 分钟论文讲不清就要求更长时长；24s 片只装得下"1 个反常识 + 1 条机制链
   + 2-3 个数字"。宁可少装，不要赶路。

## 输出格式

只输出一个 JSON 代码块（PAPER-BRIEF.json 全文），不要额外解释。
若被 validate_brief.py 打回：只修违规项，其余不动，重新输出完整 JSON。
