# 2.5D 伪立体规范（不做全 3D）

> 结论先行：**大部分"3D 感"不需要 Three.js**。用 Canvas 2D 的四招就能做出体积感，
> 而且渲染快 10 倍、改动小、不引入依赖。真 3D 只在"需要真实透视/材质/镜头运动"时才上，
> **并且必须人工决定**（见 `09-HUMAN-IN-LOOP.md`）。

参考样片：`projects/_archive/film-love-math/shots/ecg-heart.html`（心电图 → 爱心，6 秒）

## 一、四招（按性价比排序）

| 招 | 做法 | 参数（实测可用） |
|---|---|---|
| **1 斜向挤出** | 同一路径画 N 层，每层沿"光反方向"偏移一点点，颜色由深到浅 | `layers 6–10`，总偏移 `10–28px`，方向 = 光线的反方向（光左上 → 往右下挤） |
| **2 渐变描边** | 主线不用纯色，用**沿走向的线性渐变**：上亮下暗 | `#FFB3C8 → #FF5C86 → #C32B54`，中间色占 45% |
| **3 接触阴影** | 同一路径压扁 0.22 倍、模糊 16px、透明度 0.3，画在主体下方 | 偏移 `H*0.30`，`filter:blur(16px)` |
| **4 转身压缩** | 用 `scaleX = 1 - 0.14*sin(π·u)` 模拟 rotateY | 幅度 8–16%，周期 1.5–2 秒一次 |

> 第 1 招是"有没有 3D 感"的分水岭。只加高光不挤出，永远是平的。

## 二、什么时候用 2.5D、什么时候必须问人

| 场景 | 建议 | 谁决定 |
|---|---|---|
| 线条/图形/数据要有体积（本例：爱心、波形、曲线） | **2.5D** | 可自动 |
| 需要"转个身"展示侧面 | **2.5D**（squash + 挤出） | 可自动 |
| 需要真实透视、材质、真实光照、镜头运动 | **真 3D（Three.js）** | **人工确认**（成本 ×5，渲染 ×6） |
| 有实拍素材要合成 | **人工给素材**，代码负责排版与动效 | **人工** |

## 三、写进提示词的说法

```
立体感用 2.5D，不要引入 Three.js：
① 路径斜向挤出 8 层，光从左上来，往右下挤 20px，颜色 #5A0A26 → #B01E3C
② 主线用纵向渐变描边（#FFB3C8 → #FF5C86 → #C32B54）
③ 地面加压扁 0.22 倍、模糊 16px 的接触阴影
④ 每 1.8 秒做一次 rotateY 式横向压缩，幅度 12%
禁止：真实 3D 引擎、环境贴图、物理光照
```

## 四、验收

| 项 | 判据 |
|---|---|
| 有没有"厚度" | 放大到 200%，主线与挤出层之间能看到一条更暗的带 |
| 有没有"受光方向" | 全片光源方向一致（本例：左上） |
| 会不会脏 | 挤出层超过 10 层会糊，控制在 8 层内 |
| 字幕安全 | 立体形状的最低点必须高于 `y = 800`，否则压字幕 |
