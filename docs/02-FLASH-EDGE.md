# flash 的独特优势：用便宜的迭代换质量

> 很多人的直觉是"便宜模型 = 降级版"。真相是：**便宜到某个程度，用法就变了。**
> 当一条片子只花 ¥4，你的策略不该是"一次做对"，而是"做很多次，挑最好的"。

## 1. 三个杠杆，都是钱买来的

| 杠杆 | 一次成本 | 换来什么 |
|---|---|---|
| **静帧抽卡** | ¥0.1 | 同一镜头出 2–3 个方案对比。画面差异比你换三次提示词都大 |
| **整片重抽** | ¥4 | 不满意就换角度再来一版，而不是在原稿上缝补 |
| **看图迭代** | ¥0.05/轮 | 渲帧 → 看图 → 改 8 行，一天能走 20 轮 |

传统做法里，"重来"是最贵的动作；在 flash 上，"重来"是最便宜的动作。

## 2. 所以流程要反着设计

| 常规做法 | flash 做法 |
|---|---|
| 想清楚再动手，一次成型 | **先出 3 版再想**，用版本倒逼判断 |
| 修改要慎重，怕破坏 | **破坏就重抽**，比修复快 |
| 用强模型定风格 | **用 3 版静帧定风格**，你的眼睛比模型准 |
| 省 token | **省时间**，token 已经不是约束 |

## 3. 四个数字（记住这四个就够）

```
¥0.02/M   缓存命中的输入     → 风格包随便塞
¥4/M      输出               → 2000 行 ≈ ¥0.7
384K      单次输出上限        → 整片一次写完
0.5×      空闲时段折扣        → 晚上干活
```

## 4. 为什么"验收器"比"更强模型"更值

强模型的价值是**它自己知道哪里不对**。这件事可以用一个脚本替代——只要你的规格写得够细。

```
强模型的隐含能力        本生态的替代物
────────────────────    ────────────────────
"这个构图有点怪"    →   qa_check.py 的断点清单 + 你看图
"这段节奏拖了"      →   相邻 2 秒密度 + 最长静止段
"文字被压住了"      →   安全区亮像素检测
"记得改成统一配色"  →   ds-failure-modes.md 的禁令 + 你 grep 一遍
```

**结论：把"模型的自审能力"外化成脚本和清单，你就用 1/20 的钱拿到了 85% 的结果。**

## 5. 什么时候这条路会失效

诚实说清楚，免得你踩坑：

| 场景 | 为什么不灵 |
|---|---|
| 需要极强的构图直觉（大片级空镜、复杂 3D 场景） | 那是审美上限问题，脚本测不出来 |
| 需要写 5000 行以上的强耦合工程 | 长文件一致性会崩，需要更强的模型或拆模块 |
| 需要"一次就对"的商单 | 抽卡策略要时间，交期紧时会难受 |

**在这三种场景之外——知识片、数据讲解、品牌动态、MV 卡点——这套流程够用。**
