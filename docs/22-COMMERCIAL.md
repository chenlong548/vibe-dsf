# 22 · 商业化定位与合作方式

> 这份文档用于对外展示与报价沟通。所有技术能力都来自本仓库**已跑通**的链路
> （见 `docs/16-PROJECT-SUMMARY.md` 与 `pipeline_report.json` 实测），不写未验证的承诺。
> 对外口径统一为**团队**（we / our team）；品牌写法见 `brand/BRAND.md`。

## 一、我们提供什么

**VIBE·DSF** 是一套把「一句话主题 / 一篇论文 / 一个 GitHub 仓库」变成可发布知识视频的
自动化流水线：代码绘制画面、双语字幕、确定性 BGM / 音效 / TTS 旁白，逐帧渲染后由
**像素级 QA 门禁**验收，不过线不放行，最后合成 1080p 成片并留下机器可读的执行报告。

产品分两层：

| 层 | 内容 | 授权 |
|---|---|---|
| **开源核心** | CLI 流水线、10 个积木、三条内容生成线、QA 门禁、评审页、执行报告 | MIT（`LICENSE`） |
| **商业服务** | 私有化接入、定制画风/积木、系列化内容生产与团队复核 | 按范围 / 按系列报价 |

开源核心**自托管**：不依赖我们的服务器、不需要账号、无遥测；客户的模型 API Key 与素材
始终在客户手里。

## 二、适合谁

| 客户 | 典型场景 | 我们交付 |
|---|---|---|
| 海外技术科普频道 / 内容运营团队 | 稳定周更的知识短视频、系列化选题 | 系列成片 + QA/执行报告 + 可复现源文件 |
| 开发者关系 / 技术市场团队 | 产品发布解读、技术概念科普、仓库介绍片 | 项目介绍片（PROJECT2VIDEO 线）+ 定制画风 |
| 教育 / 课程团队 | 章节化长片、知识点拆解 | 长片（已验证 180s / 5400 帧）+ 章节规划 |
| 研究 / 论文传播团队 | 论文 → 大众科普片 | 论文线（PAPER2VIDEO）+ brief/plan 契约 |

共同特征：**内容以计算机技术与科普为主、需要可重复的质量标准、不想把预算花在逐帧人工剪辑上**。

## 三、边界（做什么 / 不做什么）

| ✅ 做 | ⛔ 不做 |
|---|---|
| 1920×1080 横屏、代码绘制动效、四层构图、双语字幕 | 竖屏 / 短视频平台专有画幅（实测后主动放弃） |
| 确定性 BGM、六音效白名单、TTS 旁白 + RMS 侧链闪避 | 真人拍摄、实拍素材剪辑、配音演员经纪 |
| 11 项像素级 QA、画风感知安全区、CI 回归夹具 | 托管客户的模型 API Key、代运营账号 |
| 主题 / 论文 / 仓库 → SCENE-PLAN → 成片 → 执行报告 | 付费连接器 / 闭源 SaaS 依赖（优先开源 + 本地部署） |
| 静帧并排评审页、A/B 风格抽卡 | 换 Remotion / Motion Canvas 等第二渲染路径（引擎不是瓶颈，见 `docs/11`） |

每条「不做」都是工程决策而不是缺口，理由写在对应文档里。对外沟通时如实说明，不包装成
「后续会支持」。

## 四、三档合作方式

| | **Self-host** | **Integration** | **Managed series** |
|---|---|---|---|
| 你得到 | 完整开源仓库 + 22 篇方法论文档 | 接进现有内容栈的私有化流水线 | 按系列交付的可发布成片 |
| 我们交付 | —（自行 clone） | 部署脚本、定制积木 / 画风、SCENE-PLAN 对接、验收报告、团队工作坊 | 每期成片 + QA 报告 + 执行报告 + 可复现源文件 |
| 适合 | 有工程团队、想自己掌控 | 有内容团队、希望少踩坑 | 要稳定周更、不打算自建 |
| 周期 | 即刻 | 一次接入 + 按需迭代 | 按系列排期，与内容日历对齐 |
| 计价 | 免费（MIT） | 按接入范围报价 | 按系列报价 |

**报价方式**：发现会确认选题量、片长、画风与交付节奏后给 scoped quote；这里不写统一价目，
因为成本主要取决于客户自己的模型 API 用量与定制深度。站点 `site/index.html` 的 CTA 指向
GitHub Issues / Discussions，不收集表单数据。

## 五、每期交付物（Managed series）

| 文件 | 内容 |
|---|---|
| `final.mp4` | 1080p30 · h264 + aac · loudnorm −14 LUFS · bt709 |
| `index.html` | 确定性单文件渲染源（同 `t` 同像素，可重渲任意时间段） |
| `SCENE-PLAN.json` / brief | 场景、字幕、旁白、音效卡点的机器契约 |
| `qa.json` | 11 项评分 + QA v4 画风感知边缘 + 病灶时间戳 |
| `pipeline_report.json` | 阶段耗时 / 退出码 / 产物清单 / 失败阶段（`docs/21`） |
| `final_audio.wav` + 分轨 | BGM / SFX / 旁白分轨，便于二次本地化 |
| 字幕文本 | 双语字幕，可直接进多语言版本 |

团队在交付前做**人工过目**：模型自评不作为验收依据，QA 数字 + 人眼复核双过才算完成。

## 六、质量与验收

- **硬门禁**：`avg < 8 → exit 1`，流水线停在 QA，不允许带病交付（`pipeline/qa/qa_check.py`）。
- **11 项指标**：运动/结构（密度、静止段、硬切、安全区、字幕带、首帧）+ 审美（纹理能量、
  构图重心、强调色、字幕占用）；v4 边缘检测按画风自适应（`docs/20`）。
- **确定性**：`render(t)` 是纯时间函数，同帧 SHA256 一致；局部重渲不影响其他段。
- **可观测**：每次运行都有执行报告，失败路径同样落盘（`docs/21`）。
- **回归**：CI 跑两个夹具（边缘检测 7 条 / 执行报告 8 条）+ `_probe` 规划与组装冒烟。
- **诚实边界**：工程链路端到端测过；方法论里的部分禁令来自观察、未全部做 A/B；
  竖屏不支持。这些在 `README` 与 `docs/04-AB-RESULT.md` 里都写明了。

## 七、数据与合规

- 全链路**本地运行**：无遥测、无账号体系、无外部数据回传；产物只写本地项目目录。
- 模型 API Key 由客户自持；`scripts/env.ps1` / `env-creative.ps1` 中的 token 永远是占位符，
  真实 Key 只存在于本地未提交副本（`SECURITY.md`）。
- 依赖：`numpy` / `pillow` / `edge-tts`、Chrome（CDP）、ffmpeg；均为开源或系统组件，
  不需要付费连接器。
- 上游风格数值的来源与许可见 `LICENSE` 尾段；自建部分 MIT。
- 客户素材与成片版权归客户；我们不托管、不复用、不用于训练。

## 八、成本模型

- **无 SaaS 订阅费**：客户只付自己的模型 API 用量与算力。
- 管线围绕低成本模型设计（批量场景 / QA 修复 / plan 编写）；创意帧与风格定调可选用
  强模型，按帧少量调用（`docs/01 §7`）——这是分工，不是加价项。
- 商业服务按接入范围或系列报价，**不按 token 转售加价**。

## 九、FAQ

1. **为什么不用 Remotion / 现成剪辑工具？** 引擎不是质量瓶颈；差距在画面密度、门禁执行
   与迭代速度。自研单文件 Canvas 渲染 + 像素级 QA 才能把审美变成可测数字（`docs/11`）。
2. **支持竖屏吗？** 不支持。实测过，只做 1920×1080 横屏，写进边界里。
3. **必须绑定某个模型吗？** 不必。渲染 / QA / 音频 / 合成都是模型无关的；规划层默认用
   低成本模型，创意帧可换强模型，`SCENE-PLAN.json` 是纯 JSON 契约。
4. **没有 GPU 能跑吗？** 能。当前开发环境无独立显卡：TTS 走 edge-tts，渲染靠无头 Chrome
   CDP fast 模式（0.13s/帧）。
5. **QA 8 分线能改吗？** 能，但调阈值必须同时跑回归夹具与两条实片同帧对比（`docs/20 §六`），
   不接受「为了过闸放水」。
6. **能接我们已有的字幕、素材、品牌色吗？** 能。品牌色走 `pipeline/palette.json`，
   字幕/场景走 `SCENE-PLAN.json`，这属于 Integration 档。
