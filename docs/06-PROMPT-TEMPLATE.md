# 提示词模板 v2（固定机位 · 分章背景 · 强调特效）

> 骨架来自 [claude-motion-playbook](https://github.com/PHY041/claude-motion-playbook) 的统计结论：
> 表现最好的规格都有同一套解剖 —— `<inputs><direction><structure><build><gotchas><start>`，
> 且**真正的价值在 gotchas 和确定性渲染、QA 闸门上**，不在形容词里。
> 该研究还发现：**"go all out" 这类加压措辞在盲评里不加分**（+0.08，p≈0.47），
> 而"同一个提示词会产出不同的片"——**多抽几版留最好，才是唯一可控的杠杆**。

```xml
<role>
你是一位动态设计师兼科普作者，用代码制作 1920×1080、30fps 的知识短片。
画面语言：深色底、单一强调色、数字做主视觉、一章一套背景。
</role>

<inputs>
1. 主题 / 观众要记住的一句话：【】
2. 署名（左上角水印）：【@昵称】
3. 时长：【180】秒（120–180）
4. 强调色（默认金 #C9A96A）：【】
5. 画幅：**只做横屏 1920×1080**（竖屏不做）
6. 是否双语字幕：【是，中文主句 + 英文斜体】
</inputs>

<direction>
【机位】三脚架。全片不做推镜、摇移、缩放漂移。cam() 恒返回 {s:1,dx:0,dy:0}。
       动感来自三层：背景自身运动 / 元素进出场 / 强调特效。
       **抖的是元素，不是镜头。**

【背景】一章一套，禁止全片同一背景。七章七个底色 + 各自专属纹理与运动：
       点阵上浮 / 斜光束横扫 / 网格平移 / 碎屑下落 / 同心圆扩张 / 柔光呼吸 / 光晕脉动。
       判据：七章静帧并排，不看字幕要能认出 5 章以上。

【强调】四件套，全片 3–8 个，每个前后各留 0.4 秒安静：
       ① 放大冲击 1.0→1.14→1.0，0.36s，easeOutBack —— 只给关键数字
       ② 白闪 0.14s，遮罩 0.22 —— 只给章节切换
       ③ 元素抖动 ±7px、0.22s、三次衰减 —— 只给否定/打叉
       ④ 描边注入 2px 金色、0.3s —— 只给关键词升级

【层级】一帧只有一个主角。同一帧只允许一个元素发光；第二个出现时，第一个必须退光。
       一级：当前数字/结论（≥90px）；二级：支撑图形；三级：注释 25px 灰；四级：顶栏 21px 更灰。
</direction>

<structure>
【钩子 0–8%】反直觉数字或问题，2–3 句
【第一段 8–28%】建立事实，铺点阵/网格
【第二段 28–46%】机制推演，图形必须持续运动
【反转 46–58%】给出与直觉相反的结论（这里放一次硬切）
【第三段 58–80%】另一组数字，换背景换图形
【落点 80–93%】把结论连到观众经验
【收尾 93–100%】结论卡 + 引用 + 署名
</structure>

<build>
1. 单文件 index.html；window.render(t) 纯时间函数；固定种子随机；无帧间状态。
2. 渲染：node render_frames.mjs --fps 30 --duration 【】
3. 配乐：python synth_bgm.py bgm.wav --style vibe --duration 【】 --marks 【关键秒数】
4. 合成：powershell -File build.ps1 -Audio bgm.wav
5. 每完成一章渲 3 张静帧自检（溢出/重叠/可读性），修好再下一章。
</build>

<gotchas>
- 字体加载完再截图（document.fonts.ready）。
- Canvas 中文必须手动换行，行宽上限 = 容器宽 × 0.82。
- 顶部标签/水印/时间码全片位置恒定。
- 硬切点前后各渲一帧对比 —— 最容易出错的就是那一帧（我踩过：删了变量忘改引用，整帧空白）。
- 你听不到声音：用 wave_png.py 把波形画出来检查。
- 相机一律不加位移；如果觉得"不动"，加元素和背景，不要动机位。
- 强调点超过 8 个 = 没有重点，砍掉。
</gotchas>

<start>
先给 inputs 的答案和分镜表，等确认。
再渲 3 张关键静帧定风格，确认后渲整片。
**同一个分镜出 2 版**（不同强调策略），留更好的那版 —— 这是统计上唯一有效的质量杠杆。
</start>
```

## 三条从研究里拿来的实操结论

| 结论 | 怎么用 |
|---|---|
| 长提示词不比短的好看（3.94 vs 3.88，p≈0.87） | 别把力气花在形容词上，花在 `gotchas` 和验收上 |
| 加压措辞只在"评分者看到提示词"时加分（盲评差值 +0.08） | 写"要惊艳"没用；写具体参数有用 |
| 同一提示词产出差异很大（31 条同句提示词跨 4 个类别） | **固定分镜，出 2–3 版，挑最好的**——这是可复现的提质量手段 |
