# vibe-film-ds · 用代码拍片（flash 专用）

> 本 skill **只服务 flash**，没有其他模型的兼容分支。
> 设计前提：flash **很听话，但很平庸**。所以把审美判断全部改写成**可 grep 的硬规则**，
> 并强制 **"渲帧 → 看图 → 改代码"** 回路——这是 flash 带视觉能力的最大红利。
> 配套的 12 条调优见 `docs/03-FLASH-PLAYBOOK.md`，写码前先过一遍。

## 0. 先读三份（每次开工都要读）

| 文件 | 作用 |
|---|---|
| `references/style-dna.md` | 布局/字号/配色/节奏的数值规范 |
| `references/ds-failure-modes.md` | **10 条硬禁令**，写码前贴在最前面 |
| `styles/<风格>.md`（生态根目录） | 具体画风包，选题定了再选 |

## 1. 交付契约（不可协商）

```js
window.DUR    = 140;                       // 总秒数
window.READY  = false;                     // 字体就绪后置 true
window.render = (t) => { /* 画第 t 秒 */ }; // 确定性，无副作用
```

- 单文件 `index.html`，不引 CDN、不引外部图片
- `?t=12.4` 进入抓帧模式：只画那一帧，不启动 rAF
- 禁止 `Date.now()`、无种子 `Math.random()`、跨帧全局状态
- 所有文字走内置 `drawText()`（含测量 + 折行），禁止裸 `fillText`

## 2. 五段叙事（时长按非均匀比例，见 F3 禁令）

| 段 | 占比 | 内容 | 判据 |
|---|---|---|---|
| 钩子 | 0–6% | 抛一个反直觉问题，不给答案 | 前 2 秒必须有元素进场 |
| 锚点 | 6–25% | 真实年份 + 人名 + 事件，建可信度 | 每个数字有来源 |
| 推演 | 25–70% | 动画把机制一步步跑给观众看 | 全片最重的段落 |
| 转折 | 70–88% | 给出与直觉相反的结论或数字 | 数字要放大到 ≥120px |
| 落点 | 88–100% | 连到日常经验 + 引用/署名卡 | 最后一帧不许空 |

## 3. 工作流（7 步，**每步有闸门，不许跳**）

```
① 选题核实 → ② script.md → ③ storyboard.md → ④ 3 张静帧
   → ⑤ 30 秒样片 → ⑥ 全片代码 → ⑦ QA + 合成
```

### ① 选题核实
写 `facts.md`：每个事实一行，格式 `结论 | 来源URL | 抓取日期`。
没进 `facts.md` 的数字，**不许出现在任何画面里**（F7）。

### ② 写剧本 `script.md`
旁白总量 = 时长 ÷ 3 秒/句。每句一行：`[in]–[out] 中文 / English`。
中文 ≤ 20 字。**写完自己念一遍**，念着别扭就删。

### ③ 写分镜 `storyboard.md`
每个镜头六项：时间区间 / 画面元素 / 动作（进场-停留-出场）/ 注释 / 字幕 / 转场方式。
转场必须"从内容里长出来"（线→坐标轴、卡→阵列）。**禁止淡入淡出**。

### ④ 3 张静帧（省 2 小时的关键）
只实现开场 / 高潮 / 结尾三帧，渲成 PNG：

```bash
node ../pipeline/render/render_frames.mjs --stills 3,45,132
```

**然后必须看图**（`read_image`），并逐条对照：
1. 左右镜像一下，是不是差不多？（是 → 对称癖，打回）
2. 灰度下还认得出字吗？（否 → 亮度踩踏）
3. 有没有元素压住别的元素？
4. 主视觉重心是否偏离中线 8–15%？

### ⑤ 30 秒样片
实现 hook + 第一个推演段，渲 0–30 秒。**再一次看图**，确认动效节奏不呆。
（匀速癖在这一步最容易暴露：动起来之后一眼能看出来。）

### ⑥ 全片代码（三段式，专为 384K 输出设计）

```
第 1 段：骨架 + sceneHook  →  渲 1 帧，确认风格/字体/配色对
第 2 段：一次性补齐剩下 4 个场景（利用 384K，一次吐完，不分块）
第 3 段：之后全是 patch —— 单场景 / 单常量，绝不再整文件重写
```

**为什么这么切**：分 5 次写会让变量名漂移、坐标重复（每次都要重读上下文）；
但一次写全 5 个场景又没法在中途验证风格。**"先 1 个验，再一次补全"** 是两者的交点。

第 2 段之后，任何修改都必须遵守 F4：改动 ≤5 行用 patch，并回答"改了哪几行"。

### ⑦ QA + 合成
```bash
node ../pipeline/render/render_frames.mjs --fps 30 --duration 140
python ../pipeline/qa/qa_check.py frames --fps 30 --json qa.json
python ../pipeline/audio/synth_bgm.py bgm.wav --bpm 77 --duration 140
powershell -File ../pipeline/compose/build.ps1 -Audio bgm.wav
```
**QA 总分 < 8 不许交付**。按断点清单定位，只重渲那几秒：
```bash
node ../pipeline/render/render_frames.mjs --start 41 --end 47
```

## 4. 回看回路（本 skill 的核心）

```
render_frames --stills → read_image 看帧 → 指出 3 个具体问题（带坐标/秒数）
   → 只 patch 那几行 → 重渲那几秒 → 再看
```

**规则**：
- 每次看图最多看 3 张、最多改 3 个问题，改完必须重看（看多了 flash 会失焦）
- 说"挺好的"是禁止的——必须说出"好在哪、差在哪"
- **视觉判断与 QA 数字冲突时，以数字为准**（模型会自我感觉良好，像素不会）
- 创意用温度 0.9 出 5 个方案挑 1 个；写代码用 0.3

## 5. 铁律（flash 版，全部可执行）

0. **机位固定**：不做推镜/摇移/缩放漂移。`cam()` 恒返回 `{s:1,dx:0,dy:0}`。
   动感来自三层：背景自身运动 / 元素进场退场 / 强调特效。**抖的是元素，不是镜头。**
0b. **一章一套背景**：七个章节并排看，不看字幕要能分出是哪一章。
0c. **强调四件套**：放大冲击（1.0→1.14，0.36s）/ 闪烁（2 帧白闪）/ 元素抖动（±7px，0.22s）/ 描边注入。
   全片强调点 **3–8 个**，每个前后各留 0.4 秒安静。
   详见 `docs/05-MOTION-EMPHASIS.md`。
1. 字体加载完成再抓帧（`document.fonts.ready` 后才 `READY = true`）
2. 相邻 2 秒必须有肉眼可见变化；单处静止 ≤ 4 秒
   —— **对照实验结论**：光靠"微动效"只能到 0.21% 密度（低于 0.3% 线），
   **机制推演段必须有真正的运动**（曲线生长 / 粒子扩散 / 镜头推进），不能只给版式加呼吸感
3. 一个强调色，用到底；金色只出现在深底上
4. 每句字幕 2.5–4 秒；字幕不是念稿，要比旁白更短
5. 水印、章节标签、时间码全片位置恒定（系列感来源）
6. 结尾必须有引用卡 + 署名，不许空白淡出
7. 改一句文案只重渲那几秒，不许重跑全片

## 7. 常见翻车与出路

| 现象 | 原因 | 出路 |
|---|---|---|
| 画面"对但不好看" | 审美偏安全 | 套 `styles/` 的数值包，别自己发明 |
| 动起来很僵 | 匀速癖 F2 | 全局搜 `* t` 改 ease |
| **观众说"像 PPT"** | 机位在动≠有动感；或背景全片一个样 | 见 `docs/05-MOTION-EMPHASIS.md`：机位锁死 + 一章一套背景 + 强调四件套 |
| **观众说"镜头在抖"** | 用了相机推拉/漂移 | 删掉 `cam()` 的一切位移，改抖动**元素**而不是画面 |
| 分不清现在是哪一章 | 背景没换 | 七章七底色，静帧并排要能认出 5 章以上 |
| 改一处崩三处 | 整文件重写 F4 | 回滚，改 patch |
| 渲完发现字被截 | 溢出 F8 | 统一 drawText + 0.82 行宽 |
| QA 密度低 | 场景太省 | 加"微动效层"（星点/呼吸/计数） |
