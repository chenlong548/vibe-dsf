# bgm-synth · 确定性配乐

为什么不用现成音乐：**版权风险 + 时长对不上 + 段落情绪不匹配**。
程序化配乐和代码出片是同一个哲学——**同一份脚本，永远得到同一条 wav**。

## 一条命令

```bash
# 纪录片慢速（知识片默认）
python ../pipeline/audio/synth_bgm.py bgm.wav --bpm 77 --duration 140

# 电子氛围（那类片子的常用听感：脉冲低音 + 16 分琶音 + 冲击）
python ../pipeline/audio/synth_bgm.py bgm.wav --style vibe --duration 64 --marks 24,48,60
```

| 参数 | 说明 |
|---|---|
| `--style ambient` | 77BPM，pad 为主，适合知识/哲学片 |
| `--style vibe` | **96BPM**，脉冲低音 + 16 分琶音 + 侧链感 + 冲击音，适合情绪片/科技感 |
| `--marks` | 冲击点秒数（逗号分隔）：这里放低频 boom + 前置 2.2 秒上升噪声 |
| `--duration` | 必须 **≥ 片长**，建议多 2 秒 |
| `--seed` | 固定种子 = 固定结果 |

## 验声音：画波形，不靠听

agent 听不到声音，所以"有没有静音段、段落起伏对不对"只能看图：

```bash
python ../pipeline/audio/wave_png.py bgm.wav wave.png --bpm 96 --marks 24,48,60
```

图上能看出三件事：包络有没有断、拍点网格对不对齐、冲击点有没有重量。

> **这条工具是被两个 bug 逼出来的（2026-10-22）：**
> ① `mix()` 把"秒"当成了"采样点"，所有音频被挤进开头 7 秒，后面全静音；
> ② 段落表里钩子段的 pad 增益误写成 0，开头 24% 本来就无声。
>
> 两个 bug 都**骗过了 `volumedetect`**（它给出 −21dB 的"正常"均值），只有波形图抓得出来。
> 教训：**音频必须有可视化验收**，否则你会交付一条后半段没声音的片子还以为是好的。

## 它合成什么

```
低音 pad（根音下方八度） + 柱式和弦（每 2 小节换一次）
 + 琶音（推演段才进，八分音符，带左右声像）
```

段落能量自动分配（占全片比例）：
```
0–24%   只有 pad（钩子，留白）
24–50%  + 低音（揭示）
50–82%  + 琶音（推演，最满）
82–100% 回到 pad（回落）
```

## 已内置的规范

- 44.1kHz 立体声、软限幅（tanh）
- 1.2 秒淡入 / 2 秒淡出
- 峰值自动归一到 0.72（约 −4dB），交给 `build.ps1` 再做 −14 LUFS 标准化

## 混音常识（改片子时要记住的）

| 情况 | 处理 |
|---|---|
| 有旁白 | BGM 降到 −9dB 并做闪避（ducking），人声频段 1–4kHz 让开 |
| 卡点 | 场景切换对齐到 77BPM 的拍点（≈0.779s/拍）|
| 结尾 | 最后一个和弦不要"切断"，留 2 秒自然衰减 |
| 响度 | 全片 −14 LUFS（B站/抖音/Youtube 通用），峰值 −1.5dB |

## 检查音频（听不见也能验）

```powershell
# 测响度与峰值
ffmpeg -i bgm.wav -af volumedetect -f null NUL
```
- `mean_volume` 在 −18 ~ −24 dB 之间是"背景音乐"的正常值
- `max_volume` 高于 −1 dB 就是爆音风险，重跑并调低增益

## 常见问题

| 现象 | 原因 | 解法 |
|---|---|---|
| 听起来"空" | 只有 pad，没进和弦 | 检查 `--duration` 是否大于全片的 24% |
| 听起来"糊" | 泛音太多 | 改 `pad_voice(bright=0.5)` |
| 有咔哒声 | 段落切换处没交叉淡入 | 和弦交叠 2 秒（已默认）|
| 音量忽大忽小 | 没做响度标准化 | 走 `build.ps1`，别直接拼 |
