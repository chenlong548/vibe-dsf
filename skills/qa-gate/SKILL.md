# qa-gate · 把"好不好看"变成分数

模型会自我感觉良好，像素不会。**这一层是 DeepSeek 生态里最重要的补偿机制。**

## 一条命令

```bash
python ../pipeline/qa/qa_check.py frames --fps 30 --json qa.json
```

## 它测什么

| 指标 | 定义 | 合格线 |
|---|---|---|
| 画面密度 | 每帧有百分之几的像素在变（\|Δ\|>8） | ≥0.3%（优秀 ≥0.5%） |
| 最长静止段 | 连续"几乎不动"的最长时间 | ≤2.5s（红线 4s） |
| 断点清单 | 所有静止区间的秒数——**直接告诉你该去哪儿加东西** | ≤4 处 |
| 硬切次数 | 变化像素 >25% 的帧 | 2–6 次 |
| 首帧密度 | 前 2 秒的密度 | ≥ 全片平均值 |
| 安全区 | 外框 2.5% 内是否出现明显偏离背景的内容（v4 画风感知：深底查亮溢出、浅底查暗溢出） | 无 |
| 字幕覆盖 | 85%–91% 高度是否出现空档（跳过片头尾 1s） | 无 |

## 口径与回退（v4）

默认 **v4 画风感知**：按全片亮度中位数分深/浅底，边带内偏离背景 ±96 灰阶的像素占比
≥0.3% 才算溢出（深底查亮内容、浅底查暗内容）。详见 `docs/20-QA-V4.md`。

- `--legacy-edge`：只把边缘检测退回 v3 的 `edge_max>235`，评分仍是时长预算（`qa_version=v3`）
- `--v2`：v2 全口径回退（固定阈值 + 绝对亮度边缘）
- 报告里 `edge_bleed` 只列前 10 个时间戳，**全量帧数看 `edge_bleed_count`**（评分也用它）

旧口径的两个盲区：深底中灰内容贴边抓不到；浅底正常背景全帧误报、暗色文字贴边反而漏检。
别再用「加强暗角把亮度压到 235 以下」过闸。`pipeline/qa/test_edge_v4.py` 是这部分的回归夹具。

## 怎么用（三轮闭环）

```
① 渲全片 → 跑 qa → 看断点清单
② 挑最严重的一处 → 加元素/加微动效 → 只重渲那几秒
③ 重跑 qa（帧序列不变，几秒出结果）→ 分数上去 → 交付
```

只重渲某段：
```bash
node ../pipeline/render/render_frames.mjs --start 41 --end 47
```

## 判读经验

- **密度 0.1–0.2%**：画面"基本是张图"，加微动效层（星点呼吸、数字滚动、卡片微浮）
- **密度 > 1%**：可能太吵，检查是不是每帧都在全屏抖动（那是廉价感）
- **断点集中在片尾**：典型"结尾塌陷"（F10），补署名/引用卡
- **断点出现在场景切换前**：上一段把信息讲完了在等下一段，把下一段提前 0.5 秒并做重叠
- **字幕空档但你有旁白**：字幕时间轴写错了，不是画面问题

## 与人工看帧的关系

- `qa_check.py` 负责**可测的部分**（动不动、溢不溢、空不空）
- 人工/视觉模型负责**不可测的部分**（好不好看、构不构图、有没有味道）
- **两者冲突时以数字为准**——"我觉得挺满的"经常只是错觉

## 交付标准

```
总分 ≥ 8 且 无 [X] 项 且 断点已解释（每条要么修掉，要么写明为什么留）
```
